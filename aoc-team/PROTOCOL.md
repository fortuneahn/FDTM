# AOC 팀 작업 규약 v1

## 시작과 업무 흐름
1. 파트장은 요청을 읽고 company-profile.json의 확인된 정보와 공백을 분리한다. 작업 ID, 기준일, 대상 교범, 개정 범위, 입력 자료, 소유 파일과 완료 조건을 tasks.csv에 등록한다.
2. 규정 담당은 공식 출처를 확인하고 sources.csv에 발행기관, 제목, 문서 판/개정, 시행일, 적용성, URL 또는 로컬 경로, 확인일, 검증자와 상태를 기록한다. 계획서의 법조문과 교범 인가 표시는 검증 후보다. 현재 적용 규정을 검증하기 전에는 확정 요구사항으로 인용하지 않는다.
3. 전문 담당은 교범별 폴더에서 초안을 작성하고 SOC 반영안과 interface 제안, 자료 공백을 보고한다. 출처 인용 표기는 [SRC-ID / 원문 조항 또는 페이지 / 판·개정]이다. 근거가 바뀌면 영향 교범과 SOC를 재검토한다.
4. 동시 작업자는 서로 다른 파일을 소유한다. 파트장은 registers/interfaces.csv의 단일 책임자다. 각 interface는 양쪽 담당 확인 후 AGREED가 되고, 불일치 또는 미확인은 OPEN으로 둔다. 법규를 더 엄격히 적용했다는 이유만으로 충돌이 해결됐다고 판단하지 않는다. 서로 다른 적용 범위는 요구사항별로 검토한다.
5. 파트장은 통합본을 work/integrated/<작업ID>/에 만들고 revision, 파일 목록 및 SHA256을 고정한다. 검토자에게 이 스냅샷과 근거 자료를 전달한다.
6. 검토자는 reviews/<작업ID>/에 결과를 기록한다. 결함은 rejection.yaml 형식으로 파트장에게 반환한다. 파트장은 담당자에게 수정 요청하고 새 스냅샷을 재검수한다. 재시도 횟수 3 이상이면 사람에게 판단 사항을 보고하고 영향 없는 작업은 진행한다.
7. 검토 권고 통과 후 HUMAN_REVIEW로 전환한다. 최종보고와 문서 묶음을 사람에게 제출한다. 내부 승인 증빙 후에만 APPROVED_INTERNAL로 전환한다. 외부 제출은 별도 명시 지시와 제출 기록을 요구한다. 인가/수리 사실은 당국 증빙을 기록한 경우에만 기재한다.

## 문서 작성 기준
- 강행 의무는 ~하여야 한다, 실제 허용은 ~할 수 있다로 표현한다. 모든 문장을 강행 의무로 바꾸거나 원문 권고의 효력을 임의 변경하지 않는다.
- 절차는 책임자, 발동 조건, 입력, 수행 순서, 판단/한계 근거, 통보 대상, 기록과 보존, 예외/인계로 구성한다.
- 교범별 안정적인 문서 ID와 장·절·조항 ID를 사용한다. 미제공 수치는 [자료 필요], 미확인 규정은 [검증 대기]로 둔다. 최종 제출에는 미해결 필수 항목이 없어야 한다.
- 개정 기록, 문서별 책임자/검토자/승인자, 발행일과 개정번호, LEP를 갖춘다. 각 최종 페이지에 교범명, 장절, 날짜, 개정번호, 페이지를 표시한다. 변경 단락에 개정 바를 넣는다.
- Markdown 초안은 페이지가 확정되지 않는다. 페이지는 PAGINATION_PENDING으로 두고 Word/PDF 렌더링 후에만 SOC와 LEP를 확정한다. 페이지를 추정하여 채우지 않는다.
- 실제 문서를 제작할 때 documents/pdf 스킬을 읽고 루트의 'AOC 승인 교범 양식의 사본.pdf'를 렌더링·검토하여 양식을 반영한다. 이 팀 구축 단계에서는 그 PDF의 양식 적합성을 검증하지 않았다.
- 14종은 계획서의 초기 범위다. 추가 문서와 인가/수리/신고 구분은 실제 운항 형태와 당국 요구를 검증하여 대장에 반영한다. AMP와 ERP는 별도 관리 부속물로 둔다.

## 근거 검색과 자료 관리
- source originals는 inputs/regulations, inputs/manufacturer, inputs/company에 보관한다. 유료/제한 자료는 사용자가 접근 권한을 가진 자료만 사용한다.
- 우선 파일명/목차/조항 검색으로 관련 부분을 좁힌 뒤 원문 맥락을 확인한다. 스캔은 OCR 후 원본 페이지와 대조한다. 제목만 같은 다른 개정판을 합치지 않는다.
- 이 구성에는 자동 벡터 DB·임베딩·하이브리드 RAG 서버가 설치되지 않았다. 파일 검색과 근거 대장이 기본 검색 체계다. 외부 DB 연결이나 인덱스는 별도 구축 과제로 남기며 작동한다고 보고하지 않는다.
- sources.csv의 VERIFIED는 원문·판·시행일·적용성 확인 완료를 뜻한다. 확인일만 기입한 상태는 VERIFIED가 아니다.

## 완료 조건
검수 대상 revision 고정, 필수 출처 확인, SOC 누락/미검증 없음, 운영기준과 일치, OPEN interface 없음, 차단 finding 없음, 최종 렌더링/LEP 대조 완료, 내부 승인 기록 확보. 제출 가능 여부와 내부 승인 여부를 각각 보고한다.

## 상태
교범: NOT_STARTED → DRAFT → TECH_REVIEW → RED_TEAM → REWORK 또는 HUMAN_REVIEW → APPROVED_INTERNAL. 최종 내부 승인 후 개정은 DRAFT부터 재시작한다.
SOC: UNVERIFIED / GAP / COMPLIANT / NOT_APPLICABLE. COMPLIANT는 근거·대상 조항·증빙 확인 후에만 사용한다.
Finding: OPEN / FIXED_PENDING_REVIEW / CLOSED. 작성자의 수정 완료만으로 CLOSED로 바꾸지 않는다.
