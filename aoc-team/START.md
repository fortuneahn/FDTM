# AOC 교범 작성팀 사용법

이 폴더를 작업 폴더로 열고 다음과 같이 요청한다.

> AOC 팀으로 운항일반교범(POM)을 작성해줘. company-profile.json과 제공 자료를 확인하고, 전문 에이전트 분담 → SOC 작성 → 독립 검수 → 최종보고까지 진행해줘. 부족한 자료는 표시하고 작성 가능한 부분부터 완성해줘.

개정 요청 예:

> AOC 팀으로 새 근거 자료의 영향을 분석하고 관련 교범과 SOC를 개정해줘. 기존 승인본과 비교해 개정 기록과 검수 보고서를 작성해줘.

## 먼저 준비할 정보

company-profile.json의 회사명 확인, 운항 형태, 여객/화물, 기종·형식·구성, 기지·노선, 운영기준 신청 범위, 위험물 정책, 조직·최종 승인자, 기준일을 입력한다. 모르는 값은 null로 둔다.

법령 원문은 inputs/regulations, 유효 제작사 자료는 inputs/manufacturer, 조직·회사 정책은 inputs/company에 둔다. 루트 PDF는 실제 문서 편집 시 확인할 양식 참고자료다.

## 설치된 구성

- .codex/agents/의 6개 TOML은 총괄과 5개 전문 역할을 정의한다. 루트 AGENTS.md가 기본 총괄 역할과 작업 절차를 안내한다.
- .codex/config.toml은 하위 에이전트 동시 실행을 3개로 설정한다. 현재 환경의 더 낮은 제한은 그대로 적용된다. 5개 전문 역할은 작업 의존성과 한도에 따라 나눠 실행한다.
- 모델은 현재 세션 설정을 상속한다. 계획서의 예시 모델명과 가상 tools 배열을 실제 설정으로 복사하지 않았다.
- 새 역할 파일이 현재 세션에 반영되지 않으면 이 폴더에서 새 작업을 연다. 프로젝트 설정 로딩은 호스트의 신뢰·관리 정책을 따른다. 역할 로딩이 지원되지 않아도 AGENTS.md와 TOML 지침을 읽고 역할을 명시하여 위임할 수 있다.
- 이 구성은 Codex 안에서 요청할 때 가동되는 파일 기반 팀이다. 상시 백그라운드 서비스, 자동 외부 제출, 벡터 DB는 설치하지 않았다.

## 현재 준비 상태

팀 역할·프로세스·대장·양식 구성 완료. 실제 교범 내용, 규정 현행성, 회사 운영정보, 제작사 기준, PDF 양식 적용은 아직 검증되지 않았다. 사람의 승인 전까지 모든 산출물은 초안이다.
